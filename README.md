# 取景 · 构图相机

**语言 / Language：** **简体中文** · [English](README.en.md)

本项目界面提供 **中文 / English** 切换：打开「设置 → 语言 / Language」即可选择，语言偏好仅保存在本机，不依赖联网翻译服务；切换语言不会改变照片像素、模型或构图算法。英文功能说明请参阅 [English README](README.en.md) 与 [English user guide](docs/V6-USER-GUIDE.en.md)。

V6 / Android **0.6.0** 是面向手机的构图引导相机：支持真实取景、设备倍率调节与数字裁剪、七种景别、八种构图、14 套关节火柴人姿势、直接摆放站位，以及不含辅助线的 JPEG 拍摄。人脸和人体模型在设备内运行。本轮优化连续倍率与手机操作布局，新增当前画面光线分析、可调风格、设备曝光补偿及姿势/景别/倍率/背景的协调检查；继续使用内置全部资源的 Android 离线宿主。

公开源码仓库：[weg123159/qujing-camera-open](https://github.com/weg123159/qujing-camera-open)。本仓库仅发布清理后的当前源码，不包含原开发仓库的 Git 历史、旧验证截图或已签名 APK。界面使用纯 HTML、CSS 和 ES modules；Android 工程使用系统 WebView 执行这套界面，提供相机授权、系统图片选择和文件保存，不是 CameraX 原生拍摄引擎，也没有 iOS 安装包。

## 两种运行形式

| 运行形式 | 首次使用与离线方式 | 网络与保存边界 |
|---|---|---|
| Android APK | 页面、JS、WASM、模型、示例和姿势全部装入 `assets/www/`；首次安装后也不需要下载模型 | manifest 仅声明 CAMERA，没有 INTERNET 权限。JPEG 由系统文件保存器写入用户选择的位置 |
| 手机 Web App | 先联网打开；在设置中主动选择准备完整离线资源，全部校验并写入成功后显示就绪 | 应用资源随后从 Service Worker 缓存读取。浏览器可能清理缓存、执行自身更新检查，不能据此宣称浏览器被禁止联网 |

APK 使用 `https://appassets.androidplatform.net/www/` 本地安全来源，由资源拦截器读取安装包内容，不访问该域名服务器。外部网页、网络请求和范围外资源被拒绝。设备仍需可用且足够新的系统 Android WebView；应用不包含浏览器内核。详见 [`android/README.md`](android/README.md)。

无 INTERNET 权限约束的是本应用，不能代替用户关闭整台手机的 Wi-Fi 或移动网络，也不能控制其他应用。导入和保存的系统选择器可能展示其他应用提供的云端目录，离线使用时应选择设备本地位置。

## 手机操作与倍率

取景画面和快门固定在同一屏内，底部为“拍照 / 引导 / 风格”。引导模式显示景别、构图、姿势、站位四个入口；风格模式显示五个预设和参数调节；画幅与定时在顶部，光线建议直接放在取景画面。详细选择从底部面板展开，长内容只在面板内滚动；关闭后返回对应入口。横屏把拍摄控制移到侧边。布局实现见 [`dist/style.css`](dist/style.css)，真机安全区、字体放大和旋转过程仍需设备验收。

### 倍率调节

画面底部提供倍率快捷按钮，点当前倍率即可展开原位连续滑杆，另支持双指缩放。数字倍率按时间在对数空间平滑，快速新输入覆盖旧目标；仅更新变化的读数与选中态，不在每个指针事件中重建整组按钮或重复执行完整引导。倍率来源会在界面中明确区分：

| 情况 | 可用范围与行为 |
|---|---|
| 相机视频轨道提供 zoom 能力 | 读取设备报告的最小、最大、步长和当前值，通过 `applyConstraints()` 请求调节，使用实际返回值更新界面 |
| 当前相机或 WebView 没有提供 zoom 能力 | 使用明确标注的 **1–6× 数字裁剪**，预览、检测坐标、背景分析和导出使用同一裁剪 |
| 静态照片与示例 | **1–3× 照片裁剪**，可配合平移调整可见区域 |

不会无条件展示设备不支持的 0.5×，也不把视频轨道 zoom 称为光学变焦。当前没有显式选择物理超广角、主摄或长焦镜头的功能；前后摄选择和轨道倍率可用范围取决于实际设备与 WebView。

倍率与设备曝光补偿共用串行请求队列，最短提交间隔 40 ms，合并过时目标并保留其他约束；该间隔不代表预览帧率。迟到结果不能写回已经切换的镜头。请求失败保留真实状态并显示错误，不用请求值冒充成功值。倍率改变会重置旧稳定证据和不再适用的背景参考，调节尚未结束时暂不允许拍摄或使用旧规划。数字裁剪放大的是现有图像，不会增加原始细节。实现见 [`dist/camera.mjs`](dist/camera.mjs)、[`dist/zoom-geometry.mjs`](dist/zoom-geometry.mjs) 与 [`dist/app.mjs`](dist/app.mjs)。

### 光线建议与可调整风格

点取景顶部的光线卡片，查看平均显示亮度、高光比例、暗部比例，以及在可信主体框可用时的区域明暗差。分析取自未加风格的实际裁剪画面，每隔至少 500 ms 采样一次；连续新画面确认后才开放实时 EV 建议。换源、变焦、参数请求、隐藏或过期立即清除旧结论，重复视频帧不算新证据。

只有当前摄像头提供可验证的自动曝光模式、曝光补偿范围和实际读回值时，才提供设备 EV 控制。建议以设备当前值加相对增量，按实际步长和范围执行，确认读回才报告成功。未开放 EV 时说明原因。快门、ISO 与白平衡仅提供参考，没有虚构可执行的手动参数；显示像素不能直接算出真实照度、光源色温或唯一正确曝光。

原色、清透、柔暖、胶片、黑白五个风格均可调画面明暗、对比、饱和与暖调。预览和 JPEG 使用相同参数与处理顺序；不支持 Canvas filter 的环境使用 RGBA 运算回退。原色零调整不执行颜色处理，JPEG 本身仍是有损编码。风格不会改变设备 ISO、快门或白平衡，也不恢复高光、执行降噪或多帧夜景。光线推荐只在用户点击后采用，不覆盖手动设置。风格参数在当前会话保留。

### 站位、照片与拍摄

点“站位”后，在取景画面轻点或拖动火柴人参考；也可使用左、中、右、复位与方向键微调，点“完成摆放”回到拍摄。完整人物景别操作参考脚点，中近景操作脸部中心。参考目标和实际主体位置分开保存，摆放参考不会移动照片或改写检测结果。

静态照片支持 JPEG、PNG、WebP。普通照片模式下可平移和缩放，轻点可标记实际脚点或脸中心；相机实时模式不使用手动点假装持续检测。默认山湖示例明确标注预设脚点，不自动申请相机权限或加载人体模型，主动自动检测后才使用真实结果。

拍摄提供即时快门和可取消的三秒倒数，按当前可见裁剪生成 JPEG，最大长边 2400 像素且不放大原图。照片不包含网格、目标点、检测框或火柴人。成像来自 WebView/浏览器实际提供的视频帧，没有原生相机 HDR 或最高分辨率保证。

Android 的保存按钮把 JPEG 交给系统文件保存器；只有关联请求的文件流写入并关闭后才显示成功，取消或错误仍保留照片预览。网页按实际能力显示系统文件分享，保留下载入口；分享流程返回不等于照片已经进入相册。未主动保存的照片只在当前会话中，不形成持久相册。

## 景别、构图与关节火柴人

景别决定参考比例和裁切，构图决定画面关系，姿势决定动作，三者独立。以下是本项目采用的景别约定，不是唯一摄影分类标准。

| 景别 | 参考范围 | 检测锚点 |
|---|---|---|
| 大远景 | 环境主导，人物较小 | 人体框底边中点，近似脚点 |
| 远景 | 人物与环境 | 人体框底边中点，近似脚点 |
| 全景 | 头到脚 | 人体框底边中点，近似脚点 |
| 中全景 | 膝部以上 | 人脸框中心 |
| 中景 | 腰部以上 | 人脸框中心 |
| 近景 | 胸部以上 | 人脸框中心 |
| 特写 | 脸部细节 | 人脸框中心 |

八种构图是三分法、居中、留白、黄金分割、对称、对角线、引导线和框架。引导线、对称轴和环境框架需要用户观察对齐，软件没有自动理解这些背景结构。

14 套姿势按景别筛选，结合主动选择的旅行、街景、室内或简洁背景排序；各提供身体、手、视线提示，靠墙和捧杯等动作标明条件。参考为圆头、单线骨架和 **13 个主要关节点**：颈部，以及两侧肩、肘、腕、髋、膝、踝。支持切换、翻转、隐藏和透明度调整。

这些节点是作者设置的动作模板，不是对真人关节的检测。应用没有姿态估计模型、动作完成度或姿势评分。所有姿势沿用 `200×500` SVG 坐标，头顶 `y=10`、脸中心 `(100,45)`、脚底 `y=480`；按景别等比缩放和裁切，避免不同画幅拉伸人物。参考方向翻转独立于前摄镜像。

## 模型、资源和数据

本轮没有替换检测模型，没有重新训练或微调权重；优化的是控制、坐标、时序、几何和像素规则，不能据此推导识别准确率提高。

| 用途 | 项目固定配置 | 执行方式 |
|---|---|---|
| 人脸首选 | MediaPipe Tasks Vision **0.10.14**；BlazeFace short-range，float16 version 1 | 本地 JS/WASM；CPU 委托路径仍可能需要浏览器图形上下文 |
| 人脸兼容 | face-api.js **0.22.2**；TinyFaceDetector；其包内 TensorFlow.js core **1.7.0** | 明确选择 CPU；首选初始化或实际推理失败时切换 |
| 人体 | TensorFlow.js **4.22.0**；COCO-SSD **2.2.3**，`lite_mobilenet_v2` | 仅选 `person` 类，优先独立 Worker 的 CPU 后端，必要时回退主线程 |
| 构图、站位、姿势 | 本地几何规则、背景像素启发式、预设动作库 | 没有云端生成模型、身份识别或人体骨骼服务 |

模型和许可证来源保留于 [`dist/assets/vendor/NOTICE.txt`](dist/assets/vendor/NOTICE.txt)、[`person/NOTICE.txt`](dist/assets/vendor/person/NOTICE.txt) 及同目录许可证文件。人体图文件与五个分片合计 **18,561,843 字节**，加上人体库约 20 MB；这不是包含所有人脸库、WASM、图片和代码的完整离线包大小。完整网页资源量见生成后的 `dist/offline-manifest.json`，人体固定字节与 SHA256 见 [`person/ASSET-SHA256.json`](dist/assets/vendor/person/ASSET-SHA256.json)。

APK 已把这些资源纳入打包输入，首次模型使用读取安装包内文件。网页未准备离线资源前需要下载；准备完成后由缓存提供。模型仍按实际检测需求初始化，不因只切换停机检测类型就开始推理。人体输入最长边仍为 640 像素，小人物漏检不会仅因界面数字放大而自动解决。

照片与视频帧在设备内处理，没有照片上传接口、身份库或分析埋点；导入图片对象 URL 在来源切换时释放。用户主动选择系统分享或保存目标后，由目标应用处理输出文件。

## 网页离线缓存如何完成与恢复

设置中的“下载完整离线资源”会注册 Service Worker，并依次准备页面、代码、WASM、全部模型和图片。每项检查 HTTP 状态、重定向、实际字节长度及 SHA-256；所有资源写入成功后才记录完整标记、显示离线就绪。损坏模型、登录页重定向、下载中断、配额不足均不能产生成功状态。

每个构建使用独立缓存。新版本全部准备完成后等待旧窗口关闭，不强制刷新正在拍摄的页面，也不会在失败时删除旧完整版本。运行时资源从当前版本缓存读取；应用的跨来源请求被拒绝，缺失资源不会静默回退网络，而会显示需要重新准备。检查发现缓存条目缺失后撤销就绪状态，允许主动修复。重复准备共享同一任务。

网页会申请持久存储并如实记录浏览器是否批准；批准与否、用户清理数据和浏览器自身行为都不能等同于 APK 的无联网权限。设备必须在资源完整就绪后才能依赖网页离线重开。主屏幕独立窗口配置仍存在，但添加到主屏幕本身不完成缓存。

实现为 [`dist/offline.mjs`](dist/offline.mjs)、[`dist/sw.js`](dist/sw.js) 和 [`scripts/build-offline-manifest.mjs`](scripts/build-offline-manifest.mjs)。Android 原生桥接确认本地来源和内置离线标志后，直接使用安装包资源，不注册 Service Worker、不执行这次缓存下载。设计依据见 [Service Worker 使用说明](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)、[生命周期](https://web.dev/articles/service-worker-lifecycle) 与 [持久存储请求](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/persist)。

## 引导算法与背景站位

实时主体从最大有效框初始化，后续根据框重叠、相对位移和面积变化保持几何连续；不会仅因另一人稍大就立即切换。暂时失配先返回空位置，持续失配后才重选。它不是身份识别，人物交叉和遮挡仍可能换人。照片的单次分析仍选最大有效框。

采样优先使用 `requestVideoFrameCallback`，不支持时使用 `requestAnimationFrame` 并避免重复视频帧。推理串行，根据实际耗时和后端安排间隔，复用 Canvas，不积压并行帧。观测具有独立 ID、采样时间、推理耗时和临时主体标识；停止、换源、换镜头或换模式后，迟到结果不得写回。采样时间不是硬件曝光时间。

| 引导规则 | 当前实现 |
|---|---|
| 平滑 | 时间相关的指数平滑，时间常数 180 ms；主体变化、大跳变或长间断时重置 |
| 稳定对齐 | 至少 3 条不同的新观测，跨度至少 500 ms，原始与平滑的位置、可测大小均符合参考 |
| 指令切换 | 通常需要至少 2 条新观测、180 ms 的切换缓冲；不为了平滑保留已错误的方向 |
| 低置信度 | 已知人脸置信度低于 0.45、人体低于 0.40 时清除提示；未知值不补造高置信度 |
| 失效清理 | 空结果、过期、无效时间或上下文变化清除旧位置和对齐；有效期按采样间隔限制在 700–4500 ms |
| 原始边界优先 | 原始越界、贴边与大小问题不能被平滑平均隐藏 |

这些是交互阈值，不是通过真机数据集标定的成功率。重复绘制同一个观测 ID 不算新证据。手动点、示例预设和静态照片只提供当前画面的参考结果，不经过连续稳定确认；只有点、没有可测框时不宣称已确认整体大小。

完整人物边界检查只用于大远景、远景和全景；越界不评分，贴边 1.5% 内先提醒确认头脚。中近景允许按景别裁掉下半身，脸框不能验证腰、膝、胸裁切，仍需对照参考。人体框底边只是脚点近似。

从引导详情或设置进入背景站位，冻结当前可见裁剪，由用户指定现场可站区域。V6 从实际 SVG 关节和头肩轮廓计算不同动作需要的空间，再比较当前可见像素的灰度变化、边缘密度与构图距离，最多给出三个候选。同源可信人物框明显遮住候选头肩区域时排除该候选，不把脸或衣服当作可见背景。区域放不下完整参考时返回空结果。应用不理解地面安全、可达性或三维距离；背景参考固定在二维画面，真实机位移动后应重新规划。应用候选前核对来源、裁剪、镜像、景别、动作及其翻转、倍率修订与操作代次，应用后直接回到取景。

“画面协调检查”把景别、目标比例、动作包络、当前观测、倍率及背景放在同一可见画面坐标内。大小不可测量、贴边或裁出的检测框不生成可直接采用的倍率建议；所有景别均限制放大后实测主体的边界。候选和检查只表达几何/可见像素关系，不提供虚构审美百分分。公式、阈值、接口与证据边界见 [`docs/V6-ENGINE.md`](docs/V6-ENGINE.md)。

## Android 权限、生命周期与签名

Android 最低 **8.0 / API 26**，目标 **API 35**，包名 `cn.qujing.camera`。宿主仅申请 CAMERA，明确拒绝麦克风等资源，不请求文件存储权限；导入和保存通过系统选择器。

首次相机授权时，系统权限弹窗可能暂停 Activity。宿主在请求待处理时保留 WebView，避免页面隐藏事件取消首次开启；Activity 真正进入 `onStop` 时仍拒绝未完成请求并通知页面停止相机。原生页面通过专门生命周期事件停止，普通网页通过可见性变化停止。返回键先关闭当前面板、站位编辑或倒数，再按正常 Activity 行为退出。

照片保存通过 [`dist/native-bridge.mjs`](dist/native-bridge.mjs) 的请求 ID 关联原生完成事件，避免把调用桥接函数等同于文件已保存。原生保存没有人为超时，不会在用户还选择目录时误报失败。销毁会释放权限请求、文件选择回调和 WebView。

更新安装需要使用同一包名和签名密钥。**发布签名备份应独立保管在 Git 仓库之外**，不得提交密钥、密码或把它们写进 README。构建会拒绝仓库内部的签名材料。仅有源码不能恢复丢失的发布密钥。

## 开发、检查与 APK 构建

静态发布目录为 `dist/`，没有前端框架构建步骤。不要以 `file://` 打开网页；本机开发可执行：

```sh
python scripts/dev-server.py
```

访问 `http://localhost:8000/`；网页手机访问需 HTTPS。固定模型和第三方库已在工程中，运行模块检查无需安装 npm 依赖：

```sh
npm test
node scripts/build-offline-manifest.mjs
```

修改任何发布资源后，需重新生成离线清单，再打包。清单按实际内容确定版本并更新 Worker 构建标识，不包含临时 QA 页面。可以直接运行 `node tests/<模块名>.test.mjs` 查看逐条断言。

Android 构建需要 JDK 17、Android `platforms;android-35`、`build-tools;35.0.0` 和 Python 3.9+。使用官方命令行工具，无 Gradle 运行时依赖解析：

```sh
python3 scripts/android-build.py \
  --sdk /path/to/android-sdk \
  --jdk /path/to/jdk-17 \
  --keystore /private/qujing-release.p12 \
  --password-file /private/password.txt \
  --output /path/to/qujing-camera-0.6.0-release.apk
```

Windows 使用 `python` 并替换相应路径。脚本执行 `aapt2 → javac → d8 → zipalign → apksigner`，检查签名、编译后权限、非调试标志、DEX 和所有 APK 资源字节，并生成 `.sha256` 与 `.build-report.json`。完整说明和工具链来源见 [`android/README.md`](android/README.md)、[`android/TOOLCHAIN.md`](android/TOOLCHAIN.md)。中间构建目录、APK 和签名材料不进入源码提交。
